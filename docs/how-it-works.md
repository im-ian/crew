# Crew가 동작하는 방식

README에서 뺀 개념 설명이에요. 쓰는 데는 몰라도 되지만, 봇이 왜 그렇게 움직이는지 궁금할 때 읽으면 돼요.

## 봇

봇 하나는 `agents.json`의 한 항목이에요. 이름, 작업 폴더, 모델, 아바타를 갖고 있고, 메시지를 받으면 그 봇에 지정된 `cmd`를 실행해요. 새로 만들면 그 봇이 먼저 어떤 일이나 역할을 맡기면 될지 물어요. 복제하면 복사본이 먼저 짧게 인사하고, 누구의 복사본인지 말한 뒤 어떤 일을 맡을지 물어요.

기본 명령은 각 CLI의 승인 프롬프트를 건너뛰도록 되어 있어요. 데스크톱 채팅이 TUI 권한 화면에서 멈추지 않게 하기 위해서인데, 이 플래그가 어디까지 허용하는지는 알고 쓰는 편이 좋아요.

| CLI | 기본 `cmd` |
| --- | --- |
| Grok | `grok --always-approve` |
| Claude | `claude --dangerously-skip-permissions` |
| Codex | `codex --yolo` |
| Antigravity | `agy --dangerously-skip-permissions` |
| Gemini | `gemini --approval-mode yolo` |
| Copilot | `copilot --allow-all --no-ask-user` |
| OpenCode | `opencode run --auto` |

Claude / Grok / Antigravity / Codex는 봇마다 CLI 프로세스 하나를 띄워 두고, 메시지를 그 프로세스의 stdin으로 넘겨요. Claude는 `-p --input-format stream-json`으로, Grok은 `grok agent … stdio`로, Antigravity는 `agy acp`로, Codex는 `codex app-server`로 띄워요. Grok과 Antigravity는 ACP(JSON-RPC)로, Codex는 app-server JSON-RPC로 말해요. Codex의 `--yolo`는 그 프로토콜의 승인 정책 `never`와 샌드박스 `danger-full-access`예요. app-server는 `--yolo` 플래그 자체를 받지 않아요. 답이 끝나면 봇은 바로 대기 상태가 되고, 그동안 보낸 메시지도 바로 같은 프로세스로 가요. Claude, Grok, Antigravity가 백그라운드로 돌리는 작업(CI 감시, 개발 서버)은 그대로 이어지면서 봇 옆에 표시돼요. Codex는 명령 항목이 끝나면 그 작업도 같이 꺼져요. 답 뒤에도 떠 있을 프로그램은 `nohup`이나 `open -a`로 따로 띄워요. 작업이 끝나 Claude, Grok, Codex가 스스로 다시 말하면 그 말은 말풍선이 따로 생겨요. 중지는 지금 턴만 멈추고 프로세스와 백그라운드 작업은 남겨요. Codex는 `turn/interrupt`로 턴만 끊어요. 프로세스가 죽으면 다음 메시지 때 같은 세션으로 다시 띄우고, 명령이나 모델, 추론 수준, 작업 폴더, 지침이 바뀌면 다음 메시지 때 새로 띄워요. Grok, Antigravity, Codex라도 그 모드가 받지 않는 플래그가 `cmd`에 있으면 예전처럼 메시지마다 프로세스를 띄워요.

어느 쪽이든 스트리밍 JSON만 읽기 때문에 배너나 스피너, 단축키 안내가 말풍선에 섞이지 않아요. CLI 세션 id는 봇별로 보관하니까 대화를 이어서 할 수 있고, 대화를 지우면 새 세션이 열려요.

Gemini / Copilot / OpenCode도 턴 단위로 실행하지만 세션 id는 두지 않아요. 대신 매 턴 지금까지의 대화를 프롬프트에 같이 보내요. 그 모드를 못 써서 메시지마다 띄우는 Antigravity나 Codex도 그래요.

목록에 없는 명령도 봇으로 쓸 수 있어요. `--headless`로 만들면 메시지마다 그 명령을 실행하고, 메시지는 마지막 인자로 붙어요. `--headless`가 없으면 `cat` 같은 스텁처럼 긴 PTY 세션, 즉 터미널로 남아요. 테스트나 간단한 에코 봇에 쓰면 돼요.

에이전트 CLI 바이너리는 PATH 말고도 `~/.grok/bin`, `~/.local/bin`, `~/.cargo/bin`, `/opt/homebrew/bin`, `/usr/local/bin`에서 찾아요.

핵심은 데몬이에요. 데스크톱 앱과 `crew` CLI가 Unix 소켓으로 JSON 요청을 보내면, 데몬이 에이전트 프로세스를 실행해요.

## 핸드오프

세션마다 `CREW_AGENT_ID`와 확장된 `PATH`가 들어가요. 시스템 프롬프트는 대략 이렇게 알려 줘요.

> 사용자가 `@id`를 쓰면 그건 **너에게** 다른 봇을 가리키는 것이다. 이 세션에 남아라. 필요하면 직접 `crew tell <id> <text>`를 실행해라. 답에 동료를 적을 때는 `@id`만 쓰고 바로 뒤에 띄어쓰기나 문장부호를 둬라. 이름은 Crew가 보여 주니 덧붙이지 마라.
> 이름을 바꿔 달라면 `crew agent set --name "새 이름"`을 실행해라. 봇을 만들라면 `crew agent add`를, 사이드바 그룹을 만들라면 `crew group add`를 실행해라. 반복 일을 맡기면 그 말을 cron으로 바꿔 `crew routine add`로 루틴을 만들고, 고치거나 지우라면 `crew routine edit` / `remove`를 실행해라.
> 사람에게 고르라고 물으려면 `crew ask --question "..." --option A --option B`를 실행해라. 여럿 고를 수 있으면 `--multi`, 값을 적으라고 하려면 `--input 아이디`를 보태라. 정할 게 여러 개면 답장에 늘어놓지 말고 `--question`을 반복해 한 번에 물어라. `crew ask`가 답 없이 끝나거나 CLI가 끊어도 카드는 열려 있고 답은 나중에 메시지로 온다. 다시 묻지 말고, 카드가 닫혔다고 말하지 마라. 다른 봇에게 묻지 마라.
> 서로 의존하지 않는 일 여러 개는 CLI 자체 서브에이전트(Claude Agent, grok spawn_subagent, agy invoke_subagent)에게 나눠 병렬로 돌리고, 답은 다 모인 뒤 한 번에 해라. 서브에이전트는 팀원이 아니다.
> 일을 받으면 도구를 쓰기 전에 어떻게 할지 한두 문장으로 말하고, 옆자리 동료처럼 지금 하는 일을 한 줄씩 알려 준 뒤 결과로 끝내라. 작은 일은 답만 해라.
> 나중 대화에 필요한 걸 알게 되면 `crew memory append`로 적어라. 고치거나 잊으라면 `crew memory show`로 보고 `crew memory set`으로 다시 써라. 비밀은 적지 마라.
> 팀 전체 메모와 지금 봇 목록은 공유 메모리에 있다. `crew share show`로 보고, 팀 메모는 `crew share append`로 더하고 `crew share set`으로 노트만 다시 쓴다. 봇 목록은 Crew가 매번 다시 쓴다. 그룹에 있으면 그 그룹의 메모는 `crew group memory show|append|set`으로 다룬다.
> 워크트리에서 작업이 켜져 있고 이번 턴이 그 봇의 git 워크트리 안에서 시작하면, 셸은 그 워크트리 안에 있다. 편집과 커밋과 명령은 거기서 하고, 공유 체크아웃으로 옮겨 고치지 마라. 워크트리를 또 만들지 마라. 꺼져 있거나 폴더가 git 저장소가 아니면 이 문장은 프롬프트에 없다.

상주하지 않는 CLI에게는 이 문단도 들어가요. Gemini, Copilot, OpenCode, 직접 등록한 명령, 그리고 그 모드가 받지 않는 옵션 때문에 메시지마다 프로세스를 띄우는 봇이에요.

> 답한 뒤에도 계속 떠 있어야 하는 프로그램(개발 서버, 사용자에게 띄워 준 앱)은 CLI의 백그라운드 작업으로 돌리지 마라. CLI가 그 작업을 기다리며 떠 있어서 사용자의 다음 메시지가 들어오지 못한다. `nohup <명령> > /tmp/<이름>.log 2>&1 &`이나 `open -a <앱>`으로 따로 띄우고 로그 위치를 알려라. CLI 백그라운드 작업은 CI 감시처럼 끝나면 보고할 일에만 써라.

Claude, Grok, Antigravity가 상주일 때는 이 문단을 넣지 않아요. 백그라운드 작업이 다음 메시지를 막지 않고, 그 메시지는 같은 프로세스로 바로 가요. Codex가 상주일 때는 다음 메시지가 들어오므로 그 이유는 빠지고, 명령 항목이 끝나면 작업도 같이 꺼진다는 안내만 남아요. 계속 떠 있을 프로그램은 `nohup`이나 `open -a`로 따로 띄우라고 해요.

멘션은 `@id`로 저장되고 화면에는 봇 이름으로 보여요. 입력창에 이름을 적어도 보낼 때 id로 바뀌고, 봇도 답에 동료를 `@id`로 적어요. 사용자가 이름을 여러 개 적으면 지금 봇이 답을 끝낸 뒤에, 적힌 순서대로 한 명씩 답해요. 봇이 한 턴에 여러 봇에게 `crew tell`을 보내면 그 일들은 함께 시작해요. 봇 사이의 릴레이는 사용자 메시지 하나당 최대 4홉이에요.

## 메모리

### 봇 메모리

대화 기록은 지우면 아카이브로 옮겨가지만, `$CREW_HOME/memory/<id>.md`는 그대로 남아요. 앱에서는 보거나 고칠 수 없고, 봇이 대화하다 오래 남길 만한 걸 알게 되면 스스로 `crew memory append`로 적어요. 기억해 달라고 하면 봇이 적어요. 고치거나 잊을 땐 `crew memory set`으로 통째로 다시 쓰고, 비밀번호나 토큰은 적지 않아요.

새 세션을 열 때 Grok은 `--rules`로, Claude는 `--append-system-prompt`로, Codex는 `-c developer_instructions=`로 그 봇의 메모리를 넣어 줘요. 이런 플래그가 없는 다른 CLI는 매 턴 프롬프트 앞에 넣어요. Claude와 Codex는 이어지는 턴에 처음 시스템 프롬프트를 그대로 쓰고, Grok은 시스템 프롬프트가 바뀌면 프롬프트 캐시를 잃어요. 그래서 세션 도중에 그 봇의 메모리가 바뀌면 시스템 프롬프트는 그대로 두고, 다음 턴 앞에 `[crew system]` 메모로 새 내용을 한 번 알려 줘요. 봇을 복제하면 그 메모리도 함께 복사되고, 봇을 삭제하면 그 파일도 같이 지워져요.

### 공유 메모리

`$CREW_HOME/shared.md` 하나예요. 모든 봇이 같은 노트를 봐요. 고치는 건 봇이 `crew share`로 해요. 봇 목록은 이 파일에 적히지 않아요. 프롬프트 앞의 `Shared memory` 노트가 지금 명단과 공유 노트를 같이 넣어요. 이어지는 세션에는 노트가 바뀐 턴과 대화가 압축된 다음 턴에만 붙고, 그 밖의 턴은 세션이 이미 들고 있는 사본을 써요. 매 턴 통째로 붙이면 세션마다 같은 노트가 쌓여 토큰을 써요. 마지막으로 보낸 노트는 `$CREW_HOME/cli-shared/<봇 id>`에 적어 둬요. Claude(`compact_boundary`)와 Grok(`auto_compact_*`)은 압축을 알려 주고, 슬래시 명령(`/compact` 등) 다음 턴에도 다시 보내요. 압축을 알려 주지 않는 Codex와 세션이 없는 CLI는 매 턴 보내요. `crew share set`은 노트만 바꾸고, 명단은 Crew가 그 턴의 봇 목록으로 다시 만들어요.

### 그룹 메모리

사이드바 그룹 하나의 노트예요(`$CREW_HOME/group-memory/<그룹 id>.md`). 그 그룹에 있는 봇만 `Shared memory` 노트의 `# Group memory` 단락으로 함께 읽어요. 그룹 설정에서 직접 고치거나, 봇이 `crew group memory append` / `set`으로 고쳐요. 그룹을 지울 때만 같이 지워져요.

## 메시지 전달과 중지

- 설정의 메시지 전달은 기본이 인터럽트예요. 작업 중일 때 보낸 메시지가 지금 턴을 멈추고 그 메시지부터 시작해요. 대기열로 바꾸면 순서대로 기다려요. 대기열은 봇당 최대 32개예요.
- 대기 중인 메시지는 그 자리에서 수정하거나 취소할 수 있어요. 입력창이 비어 있으면 `↑` / `↓`로 대기 중인 줄을 고르고 Enter로 수정해요. Enter는 보내지 않아요.
- 대기열 모드에서 바로전송을 누르면, 봇이 작업 중이어도 지금 턴은 멈추지 않고 그 줄이 턴 다음에 혼자 나가요.
- CLI가 한 줄도 쓰기 전에 멈추면 그 턴에 묶인 메시지는 대기열 앞으로 돌아가고, 다음 메시지나 바로전송을 기다려요.
- 시작 후 첫 출력이 없을 때도(grok 15초, claude·codex 30초) 같이 돌아가고, 채팅에 `CLI가 응답하지 않습니다`가 남아요. 이어가던 세션이 그래서 멈추면 그 세션을 버리고, `CLI가 이전 세션에서 응답하지 않아 새 세션으로 다시 보냅니다`라고 남긴 뒤 새 세션에서 한 번 더 보내요. 새 세션도 답이 없으면 `CLI가 응답하지 않습니다`와 함께 대기열에 둬요.

## 그룹 작업 폴더

그룹에 작업 폴더를 정하면 그 그룹 안 봇의 작업 폴더가 그 폴더로 바뀌어요. 그 그룹으로 옮긴 봇과 그 그룹에서 새로 만든 봇도 거기서 일해요. 폴더는 선택이에요.

## 스킬

설정에서 이름과 본문을 마크다운으로 저장해요(`$CREW_HOME/skills/<이름>.md`). 입력창에 `/이름`을 치면 본문이 들어가요.

## 루틴

일정은 5필드 cron이에요. 패널에서 스위치를 바꾸면 그 봇의 채팅에 남고, 봇이 알았다고 답해요. 채팅에 남은 그 안내를 누르면 루틴 패널이 열려요. 실패한 실행도 그 분(minute)의 슬롯을 쓴 것으로 쳐요. 같은 분에 다시 실행되지 않도록요.

## 사용량

사용량 버튼은 로컬에서 읽을 수 있는 값만 써요. API 키를 등록해야 하는 AI는 넣지 않아요.

| CLI | 읽는 곳 |
| --- | --- |
| Claude | Crew가 돌린 Claude 턴이 알려 준 한도 |
| Grok | `~/.grok/logs` |
| Codex | `~/.codex/sessions` |
| Antigravity | `agy -p /usage` (5분 캐시) |

마지막으로 읽은 값은 `$CREW_HOME/plan-usage-*.json`에 남겨요.

## 첫 실행

`agents.json`이 아직 없으면 저장소의 [`agents.example.json`](../agents.example.json)을 복사해서 시작해요. 예시 로스터는 `grok`(`grok --always-approve`)과 `shell`(`cat`) 두 봇이에요. `examples` 블록의 Claude / Codex는 참고용이라 자동으로 등록되지는 않아요.

## 워크트리

설정 > 일반의 「워크트리에서 작업」은 기본으로 꺼져 있어요. 켜면 봇의 폴더가 git 저장소일 때, 그 봇만의 워크트리를 만들어 거기서 명령을 실행해요. 설정된 폴더가 저장소의 하위 폴더면 워크트리 안의 같은 위치에서 시작해요. 워크트리는 봇과 저장소마다 하나이고 다음 턴에도 같은 곳을 씁니다. 공유 체크아웃의 커밋되지 않은 변경은 가져가지 않아요. git 저장소가 아니면 설정된 폴더에서 그대로 일해요.

켜져 있고 이번 턴이 워크트리에서 시작할 때만 기본 프롬프트에 그 경로와 공유 체크아웃 경로가 들어가요. 봇은 그 워크트리에서 편집하고 커밋하고, 공유 체크아웃으로 옮겨 고치지 않아요. 꺼져 있으면 프롬프트는 이전과 같고, 봇은 설정된 폴더에서 실행돼요.

## 데이터 위치

기본 경로는 `~/Library/Application Support/crew`이고, `CREW_HOME`으로 바꿀 수 있어요.

| 경로 | 내용 |
| --- | --- |
| `agents.json` | 봇·루틴 |
| `groups.json` | 사이드바 그룹과 그룹 작업 폴더 |
| `group-memory/<그룹 id>.md` | 그룹 메모리 |
| `locale` | `ko` 또는 `en` (알림·CLI 라벨) |
| `roster.md` | 저장된 봇 명단 사본 |
| `shared.md` | 공유 메모리 노트. 봇 목록과 함께, 바뀌었거나 압축된 다음 턴에 최신으로 전달 |
| `memory/<id>.md` | 대화를 지워도 남는 그 봇의 기억 |
| `skills/<이름>.md` | `/이름` 스킬 |
| `transcripts/<id>.jsonl` | 1:1 대화 |
| `cli-sessions/<id>` | Grok/Claude/Codex 세션 id |
| `cli-memory/<id>` | 그 세션이 아는 메모리 (바뀌면 알려 주려고) |
| `cli-shared/<id>` | 그 세션에 마지막으로 보낸 공유 메모리 노트 (바뀌거나 압축되면 다시 보내려고) |
| `archive/` | 지운 대화 |
| `uploads/` | 첨부 파일 |
| `crew.sock` / `crew.pid` | 데몬 |
| `crew.log` | 데몬 로그 |
| `plan-usage-*.json` | 사용량 버튼이 마지막으로 읽은 값 |
| `worktree` | `on`이면 봇이 git 워크트리에서 작업. 없거나 그 외에는 끔 |
| `worktrees/<저장소>/<봇 id>` | 그 봇의 git 워크트리. 봇과 저장소마다 하나를 다음 턴에도 다시 씀 |
